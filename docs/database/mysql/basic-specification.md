# MySQL 基本设计规范

为了在软件生命周期内规范数据库相关的需求分析、设计、开发、测试、运维工作，便于不同团队之间的沟通协调，以及在相关规范上达成共识，提升相关环节的工作效率和系统的可维护性。同时好的规范，在执行的时候可以培养出好的习惯，好的习惯是软件质量的保证。

## 一、使用Innodb存储引擎

<font color="red">所有表必须使用 InnoDB 存储引擎</font>

没有特殊要求（即 InnoDB 无法满足的功能如：列存储，存储空间数据等）的情况下，所有表必须使用 InnoDB 存储引擎（mysql5.5之前默认使用MyISAM，5.6 以后默认的为 InnoDB）。InnoDB 支持事务，支持行级锁，更好的恢复性，高并发下性能更好。

## 二、字符集统一使用utf8mb4

<font color="red">数据库和表以及字段的字符集和排序规则统一约定为 utf8mb4 和 utf8mb4_general_ci。</font>

兼容性更好，统一字符集可以避免由于字符集转换产生的乱码，不同的字符集进行比较前需要进行转换会造成索引失效。考虑到存量系统大部分使用了Mysql5.7，约定排序规则使用 utf8mb4_general_ci。

:::tip
- Mysql5.7: The default MySQL server character set and collation are latin1 and latin1_swedish_ci.
- Mysql8.0: The default MySQL server character set and collation are utf8mb4 and utf8mb4_0900_ai_ci.
--------
- MySQL5.7 服务器字符集 utf8mb4 对应的默认排序规则是 utf8mb4_general_ci。
- <font color="red">utf8mb4_0900_ai_ci 在 MysSQL5.7 的排序规则中不存在。</font>
--------
- https://dev.mysql.com/doc/refman/5.7/en/charset.html
- https://dev.mysql.com/doc/refman/8.0/en/charset.html
:::

:::tip
MySQL 数据库的  “utf8” 并不是真正概念里的 UTF-8。目前可见字符集都只需要3个字节，包含了所有字符。但是问题出在 unicode6 系列编码上，它们需要 4 个字节，这部分就是有名的 emoji。所以，如果我们的数据库使用默认字符设置，是无法存储 emoji 表情的。MySQL 在 5.5.3 之后增加了 utf8mb4 的编码，mb4 就是 most bytes 4 的意思，专门用来兼容四字节的unicode，因此可以用来存储 emoji 表情。
:::

## 三、每张表设置一个主键ID

由于 InnoDB 组织数据的方式决定了需要有一个主键，如果没有比较好的主键 ID 方案，或者表中的数据无法实现主键标识，可以使用自增量作为主键 ID。

:::tip 提示
主键ID单调递增可以有效提高插入的性能，避免过多的页分裂、减少表碎片提高空间的使用率。
:::

## 四、禁止使用null值作为列的默认值

表字段除 TEXT 等类型外，默认值不允许出现 null 值，使用 `0` 或者空字符串`''`来代替 null。

## 五、禁止建立预留字段

<font color="red">禁止在表中建立预留字段</font>

预留字段的命名很难做到见名识义，预留字段无法确认存储的数据类型，所以无法选择合适的类型，特别是在数据量很大情况下，对预留字段类型的修改，会对表进行锁定。

## 六、禁止存储大数据

<font color="red">禁止在数据库中存储大的数据，包括图片、文件等大的二进制数据</font>

数据库存储大的数据会短时间内造成数据量快速增长；数据库读取数据时会进行大量的随机 IO 操作，所以要避免存储大的数据；通常文件存储于文件服务器，数据库只存储文件地址信息

## 七、禁止使用外键

外键会导致表与表之间耦合，UPDATE 与 DELETE 操作都会涉及相关联的表，十分影响 SQL 的性能，甚至会造成死锁。如果有外键完整性约束，需要应用程序控制

## 八、添加注释

<font color="red">所有表和字段都需要添加注释</font>

添加表和列的注释，从一开始就进行数据字典（DDL）的维护

## 九、禁止直接连接生产环境数据库

测试环境只能连接测试数据库，为了减少开发成本，开发环境可以连接测试数据库，<font color="red">如果开发环境需要连接生产环境数据库的话，必须使用 GUI 工具，并使用 SSH 通道的方式连接</font>。

## 十、建议性约定

- 单表列数目控制在一定的数量内，如：30
- 单表行数控制在一定的大小内，单表行数超过 500 万行或者单表容量超过 2GB，才推荐进行分库分表。
- 尽量做到冷热数据分离，减小表的宽度，如：经常一起使用的列放到一个表中
